# v0.4.3 (2026-11-19)

A fix release for the watchdog's outage and shutdown paths. During an outage, restarting gluetun
started the protected services again before the tunnel was verified; it no longer does. The
lockout shutdown now stops a crash-looping gluetun, the `docker stop` fallback works when Compose
cannot read the project, and gluetun's Docker DNS block survives reconnects. The test suite gains
mutation testing, a Docker model checked against real Docker, and whole watchdog scenarios.

## Upgrading

- **Deploy:** `./stremio stop`, then `./stremio start`. This recreates `gluetun` with the new DNS
  block rule (`gluetun-post-rules-v2`) and restarts the watchdog on the new code.
- **Compose:** the watchdog's gluetun restart now uses `docker compose restart --no-deps`. A
  Compose release too old for the flag fails that restart; the outage then runs out its budget
  with the services stopped and locks out, so check `docker compose restart --help` lists
  `--no-deps` if you run an old Compose.
- **Development:** `uv sync` installs `mutmut`, a new dev dependency.

## Fixed

- **Outage restarts (`guard.py`):** the watchdog's outage path stopped the protected services and
  then ran `docker compose restart gluetun`, which also restarts every service in gluetun's
  namespace and so started them again before the tunnel was verified, on every restart until the
  outage ended. The restart now passes `--no-deps`. It affected every provider, and NordVPN
  whenever its endpoint lookup failed (otherwise gluetun is recreated, which never had this
  effect). gluetun's kernel firewall still blocked traffic outside the tunnel throughout.
- **Stopping gluetun (`guard.py`):** the lockout shutdown counted only a `running` gluetun as
  active, so a crash-looping (`restarting`) or paused gluetun read as stopped, got no
  `docker stop` fallback, and was logged as stopped. It now needs Docker's confirmation that no
  active state remains, like every other stop path (`docs/watchdog.md` already promised this).
- **`docker stop` fallback (`guard.py`):** the stop paths' fallback found containers through
  `docker compose ps`, so when Compose could not read the project (a broken file, or a Compose
  release that rejects it) nothing could be stopped. It now finds them by Compose's labels with
  plain `docker ps`, matching this checkout's project name or working directory, so another
  stack's service of the same name is never touched. It is still one query per service.
- **gluetun DNS block (`docker-compose.yml`, `guard.py`):** the Docker DNS block in gluetun's
  `OUTPUT` chain now uses `-j DROP` (`gluetun-post-rules-v2`) instead of `-j REJECT`. gluetun's
  rule parser could not read `reject-with`, so every reconnect to a new VPN server left its old
  endpoint rules in the chain. The guard now requires the `DROP` form; recreating gluetun clears
  any rules left behind.
- **Dead code (`comet_gateway.py`):** removed `CometGatewayManager.status()`, which nothing called
  and which ran the module's only `docker inspect` without a timeout.

## Added

- Test-quality tools (`docs/test-quality.md`): mutation testing with `mutmut` and
  `scripts/mutation_report.py`, `scripts/fix_site_coverage.py` and `scripts/test_overlap.py`.
- `FakeDocker` (`tests/docker_fake.py`): a stateful Docker and Compose model for tests, held to
  real Docker by `tests/test_docker_fake_contract_docker.py` (`STREMIOGUARD_DOCKER_TESTS=1`); the
  stop-path tests use it.
- Whole watchdog scenarios (`tests/test_watchdog_scenarios.py`): the real orchestrator and guard
  against FakeDocker through an outage, a recovery, rejected credentials, a leak and a crash loop.
- Every test that replaces a guard method now uses `autospec=True`, so a replacement must accept
  exactly what the real method accepts.
- Tests for gaps the first mutation run found: `stop_gluetun` against real `docker compose ps`
  states, the stop path's last-resort service list against `docker-compose.yml`, never reusing a
  SAFE verdict while gluetun's identity is unknown, `EXPECTED_VPN_IP` enforcement and its
  canonical comparison, failed `nginx -t` and reloads, bounded Docker queries in the gateway, and
  the IP probe's read cap, deadline and daemon thread.
