# v0.4.4 (2026-11-25)

A maintenance release. The Comet canary can merge upstream Comet releases again, and reports a
release whose tests fail instead of failing silently. The gateway's nginx and the Stremio server's
base image move to their current digests.

## Upgrading

- **Deploy (optional):** `./stremio stop`, then `./stremio start`. This recreates `comet-gateway`
  on the new nginx digest, whose `linux/amd64` image is unchanged, and rebuilds the Stremio image
  on its new base when Stremio is enabled.
- **Comet:** once the canary has merged the pending Comet release into the lock, pull `main` and
  promote it with `./stremio comet update apply`.

## Fixed

- **Comet canary (`tests/test_comet_integrity.py`):** a test asserted the lock's exact
  `tested_digest`, so every bump the canary validated failed the test suite and was never merged
  (since 2026-11-16). It now checks the lock's image and the digest's form.
- **Canary reporting (`.github/workflows/comet-canary.yml`):** a drift issue is filed when the test
  suite fails on a validated bump, not only when the patches fail.

## Changed

- **nginx (`docker-compose.yml`):** `nginx:1.31.9-alpine` is pinned to its new digest,
  `sha256:fb4658584bd9`. The new image index only adds `linux/riscv64`; every other platform,
  including `linux/amd64`, is the same image as before. The real-container tests pin the same digest.
- **Stremio server base image (`docker/stremio/Dockerfile`):** `tsaridas/stremio-docker` moves to
  `sha256:4e14aefecf87` (Dependabot, #47).
